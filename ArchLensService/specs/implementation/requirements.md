## 1. 产品目标与范围

ArchLens 帮助工程人员回答：系统现在如何工作，目标变化有哪些兼容性差异，哪些对象和业务入口受影响，依据是什么，还缺什么证据，以及应该如何改造和验证。发现依赖不等于确认缺陷，提出替代方案不等于证明行为等价。

| 场景 | 调查范围 | 输出重点 |
| --- | --- | --- |
| 字段变更 | 列改名、删除、类型变化及上下游使用 | 直接引用、字段传播、契约影响 |
| 数据库替换 | 源/目标产品、版本、扩展、配置与访问方式 | 能力差异、SQL/驱动/事务依赖、切换及回退风险建议 |
| MySQL → PostgreSQL | 类型、方言、自增、标识符、排序规则、函数、事务、索引 | 版本适用的兼容问题、替代方案、验证清单 |
| Oracle → PostgreSQL | 上述维度及过程、包、触发器、同义词和特有语义 | 对象级问题、应用调用影响、人工决策项 |
| C# → Java | 业务边界、类型、框架、依赖、异步、异常、序列化、部署配置 | 语义差异、能力对应、行为验证建议 |
| 代码重构 | 模块拆分/合并、方法移动、接口调整、调用和状态/副作用 | 受影响模块、公共契约、不变量与回归范围 |
| 框架及依赖升级 | 版本接口、配置、传递依赖和行为差异 | 兼容性清单及影响路径 |

以上是目标场景目录，不是当前支持矩阵。每个版本必须声明实际覆盖的产品/语言版本、语法与对象种类；未覆盖场景也应能被明确拒绝或列为未知，不能模拟成功。

## 2. 已确认事实、建议和待定项

- 已确认：只做分析调查；不自动修改被分析代码、业务数据库或部署环境。允许保存 ArchLens 自身的调查记录、证据和报告。
- 已确认：Java21 核心包含有限 Java/MyBatis 列分析、SQL/C# 词法特征和 Java AST 场景规则；模型已有六工具编排循环，仍受支持矩阵和明确文件清单限制。
- 已实施范围：MySQL 8.0.x/Oracle 19c → PG16、C#12 → Java21、Java21 重构及 Boot/JDK/HttpClient 的明确版本子集，详见 [规则矩阵](../../docs/scenario-rules.md)。这些是产品支持范围，不是用户生产环境版本。
- 待定：用户项目的实际版本/配置、真实项目规模、运行时效目标、生产部署及保留策略；未注册版本组合需独立实现和验收。
- 隐私边界：旧描述接口只发送描述。新增 Agent 发送用户目标、技术字段、约束、回答、规则元数据和匿名证据摘要；不自动上传源码、路径、业务对象名、数据库地址或凭据。更广数据范围需要另行明确。

## 4. 非功能约束和排除范围

默认不读取业务行数据，不执行被分析项目的构建脚本、测试、存储过程或任意 SQL。Agent 可以建议用户在隔离环境运行验证并接收其结果，但该结果必须注明来源、环境和是否独立核实，不能冒充自身验证。

工具调用必须有参数校验、访问边界、取消和资源预算；数据源账号只读并限制元数据范围，数据库网络连接另需数据源授权。无权限、解析失败、版本未知和不支持语法均是可报告状态。分析只支持已覆盖的语义，不能以语言模型一般知识保证跨语言等价。

排除：自动代码转换或补丁应用、DDL/DML 执行、数据搬迁、数据库切换、生产部署、生产回滚。报告可以提出改造顺序、数据校验和回退检查建议，但不携带执行器或调用执行命令。ArchLens 自身存储建设与业务数据库迁移执行必须在名称和权限上区分。

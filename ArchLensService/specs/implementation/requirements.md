## 1. 范围与完成含义

产品目标：用户提供代码来源、按需业务数据库连接、目标环境和自然语言目的，系统自主拆解调查问题、采集授权证据、比较方案并输出可审阅、可实施的迁移设计。目标可以组合 .NET 平台迁移、数据库迁移、信创环境适配、重构和组件升级；信创不自动等于转 Java。

| 等级 | 范围 | 完成产物 |
| --- | --- | --- |
| A0 现状调查 | 盘点、有限规则、覆盖与未知项 | 调查报告、证据清单 |
| A1 迁移设计 | 自主补查、方案比较、实施任务、验证设计 | MigrationPlan、工作项、验证计划、决策记录 |
| A2 设计验证 | 已授权隔离环境中的代表性验证及方案修订 | 与方案、快照、环境绑定的验证记录 |
| A3 实际实施 | 修改真实项目、搬迁业务数据、生产切换 | 不属于本轮需求，另行设计 |

COMPLETED 只表示约定范围的设计交付完成。A1 可以保留显式 NOT_RUN 的执行验证计划；A2 的必需执行项必须具有适用且通过的记录。不能把模型解释、测试建议、报告生成或局部样例通过显示为“迁移完成”。

首个样例限定一个小型 .NET 数据访问模块、MySQL 合成测试库、一个接口/服务方法、所涉 SQL/对象及业务不变量。至少包含不兼容特征、证据缺口和保留行为。目标 Java 及数据库版本/兼容模式必须明确；金仓可作为候选，未确定实测版本前保留条件化草案。

## 2. 当前基线与待开发边界

以下是源码静态核对的复用基线，不是本次运行验收。详细产品/版本差异和历史证据见现有项目总结。

| 当前已有资产 | 明确边界 | 后续要求 |
| --- | --- | --- |
| 原生网页、Node 本机适配、Java 21/Maven CLI | 没有持久任务调度、LangGraph 或生产身份体系 | 复用页面与 Java 核心，新增 TS worker |
| 三模式、.NET 清单、MySQL/Oracle/KingbaseES/DM 元数据与候选访问路径 | .NET 以声明盘点为主；后三类数据库缺厂商实库验收；候选不等于绑定 | 分能力补齐语义与厂商验证 |
| 调查引擎 0.8、规则包 1.1/25 条规则 | 固定范围；MySQL8.0/Oracle19→PG16 与 C#12→Java21 不能推广为任意组合 | 能力画像、方向规则及组合设计 |
| 六工具 Agent、匿名摘要、最多六条解释、澄清新修订 | 没有语义读取、MigrationPlan 或中间工具崩溃恢复 | 新持久规划循环与计划契约 |
| PG 修订、哈希封存、180 秒租约、epoch；Neo4j 可重建投影 | 旧 checkpoint 仅来源清单；无自动续租调度 | 新运行表、幂等账本、认可检查点与恢复 |

数据库采集、迁移规则、目标环境验证分别公布支持矩阵。自身 PostgreSQL 存储不表示已支持 PostgreSQL 业务源采集。目标环境当前仅为声明，不视为已评估。

## 3. 功能与质量需求

每项 MIG-Rxx 对应详细设计同编号 MD-Dxx；表末给出验收映射。下列“必须”约束待实现的新产品，现有旧接口的有限行为按兼容策略保留。

### MIG-R01 设计目标及范围

- 用户必须能声明 A0/A1/A2、必需模块/对象/路径、业务不变量及可接受的非阻塞未知项；完成判断以该固定范围为依据。
- 系统必须区分已观察事实、推断、方案建议、用户决策和实际验证，不以置信度或多个模型一致代替证据。
- 停机、成本、数据丢失容忍度等业务条件缺失且影响选择时，必须提出具体澄清；不能自行承诺工期或选定双写策略。

### MIG-R02 三模式与输入

- CODE_ONLY 必需代码来源和目的；DATABASE_ONLY 必需业务源或显式离线结构和目的；JOINT 必需两类来源。单项模式不要求无关连接；联合模式缺来源必须明确阻塞或由用户修改范围。
- 请求包含源/目标环境、版本/模式、约束、不变量、验收范围、数据策略、授权工具和预算。离线结构标记为用户提供、未在线核实。
- 凭据独立绑定，固定请求仅保存 credentialRef/policyRef；密码轮换且数据源身份不变不隐式改变修订。端点、账号、模式或权限策略变化需新修订并重新核验。

### MIG-R03 技术路线与模型边界

- 新编排采用 LangGraph TypeScript worker，按需使用 LangChain 模型组件；Java 继续负责确定性采集、事实与封存。首期单主 Agent 配专业工具和独立审查。
- 模型供应商可适配，但切换不自动扩大外发范围或启用云 trace。Node/LangGraph 具体版本由 P0 实验后锁定，不从旧 Node 18+ 要求推断兼容。
- 采用框架不得降低既有证据、权限、版本及失败检查。

### MIG-R04 部署与职责

- 本机单用户模式中，关闭浏览器不终止已入队运行；worker 重启后能依据持久账本恢复。原生页面和 Java 核心继续复用。
- Node 接收/查询请求，Java 持有业务写权限，worker 仅提出动作并经工具边界执行，验证服务只操作登记测试环境。
- 新运行不得嵌套或同时由旧 Java Agent 循环与 LangGraph 循环控制；旧运行仍走旧接口。

### MIG-R05 契约与证据身份

- 请求、计划、工具协议、事件、规则、模型配置及检查点均记录独立版本。未知属性/版本/枚举、跨快照引用或失效票据必须明确拒绝。
- 证据必须包含来源哈希、对象身份、生产工具版本及可核对定位；无法精确定位时保留真实粒度。
- TS/Java 使用同一规范化 JSON/哈希规则和契约样例；跨运行复用必须通过显式导入及哈希、范围、能力检查。

### MIG-R06 采集、语义与覆盖

- 本地来源只在授权根目录和预算内发现读取；Git 来源固定 commit、独立副本并报告 submodule/LFS 范围。不执行仓库 hooks 或项目代码来完成静态发现。
- .NET 逐项目保留 Framework/Core/现代 .NET/Standard、语言、SDK、TFM、编译条件。Roslyn 的 C#/VB 能力逐项发布；F# 不被默认纳入 Roslyn 语义。
- 静态分析不运行 MSBuild、restore、项目 analyzer/source generator；缺引用程序集或条件时报告绑定缺口。真实构建只能进入隔离验证模式。
- 数据库按产品/版本/账号可见范围采集，定义读取只用固定系统查询；默认不读业务行。缺权限、TLS 未核验、非原子观察和缺定义均进入报告。
- 代码→访问 API→SQL/ORM→对象的每段分别记录候选、歧义、绑定或未知。覆盖分母来自授权范围，分别统计发现、采集、解析、绑定、规则与验证。

### MIG-R07 方向规则与组合目标

- 源特征、目标能力、映射规则及成对例外分别建模；源→目标规则不能自动反转，兼容模式与版本须匹配。
- 金额/精度、时间、NULL/空串、排序、生成键、SQL、过程、驱动及事务等维度按已发布能力检查。采集成功不能证明迁移兼容。
- 多目标方案需检测框架、数据访问层、事务、驱动和 OS/CPU 冲突，合并重复工作项并比较分阶段路线。
- 官方资料/历史方案的来源与版本可追溯。模型或检索产出的候选规则经独立验证发布前不得变成规则事实。

### MIG-R08 结构化设计交付

- MigrationPlan 必须包含现状与覆盖、目标架构、备选及取舍、对象处置、实施任务、验证计划、切换/回退设计、风险未知项和证据/决策引用。
- 工作项须有稳定 ID、范围、原因、依赖、前置条件、产物、完成标准、验证项和优先级依据；依赖无环。缺工期依据时不填精确数字。
- 调查任务与开发实施任务分开，不能把“设计了修改”记为“修改已实施”。JSON 为权威结构，Markdown/页面同源呈现。

### MIG-R09 自主调查及审查

- 系统能生成调查任务 DAG，选择可执行工具、观察新证据、补齐缺口、比较方案、执行独立审查并据反例修订。
- 任务状态、依赖、尝试、预算与产物可回读；跳过任务必须说明原因并保留覆盖缺口。
- 连续无进展、模型不可用或格式失败应有界停止并保存部分结果。重要决定不能只留在压缩对话中；摘要不成为新事实。

### MIG-R10 状态、修订与恢复

- executionState、designStatus、validationStatus 以及规则 outcome 独立呈现。PG 决定业务状态，框架 checkpoint 不决定业务完成。
- 新 migration 表与旧 investigation 表各自维护修订及状态；旧报告通过 legacyRunRef 导入，原始哈希不改写。
- 租约、worker、epoch、状态、请求及修订约束每次工具执行和封存。同 run 只有一个有效调度者；过期/取消/取代后的回执不得发布。
- 澄清答案绑定 questionSetHash、parentArtifactHash、expectedRevision；原子消费并创建一个下一修订，新 run 从新请求启动，旧 interrupt 不被继续消费。
- 同输入故障恢复核对认可 checkpoint、版本和产物，以新 epoch 恢复；认可指针防旧 epoch 及同 epoch 乱序倒退。工具/外部作业去重不依赖 epoch。

### MIG-R11 工具桥接与失败语义

- 工具注册公开业务参数，宿主补充范围/票据/凭据引用；Java 再校验权限和适用版本。不得接受模型自行定义工具、路径或任意业务 SQL。
- UTF-8 JSON Lines 具有消息大小、超时、退出码和稳定错误契约；大产物用受控引用，日志不污染协议。
- 临时网络故障有限重试；权限/鉴权失败不盲目重试；存储失败不发布成功回执；已持久产物可对账恢复。

### MIG-R12 模型数据策略

- SUMMARY_ONLY 保持现有匿名摘要边界；SCOPED_SEMANTICS 提供稳定别名及结构关系；SCOPED_SNIPPETS 仅在配置授权后发送有限源码/定义片段。
- 凭据、连接串、业务行及敏感日志不进入 prompt/checkpoint/导出。源码可能含秘密，须检查脱敏；脱敏影响语义时形成缺口。
- 源码/注释/外部文档中的指令作为数据，不能改变权限。每次模型请求记录策略版本及证据/内容哈希；云 trace 默认关闭。

### MIG-R13 验证及完成门槛

- V1 检查结构/引用，V2 检查已实现的静态设计条件，V3 在独立环境验证编译、SQL/DDL、契约和行为差异，三者证明范围分别呈现。
- 每个关键假设/不变量关联验证项或明确外部确认。人工导入结果默认 EXTERNAL_UNVERIFIED，不冒充系统执行。
- V3 必须使用独立账号/环境、合成数据和资源上限；业务源连接不能执行模型生成 SQL。
- 完成须满足必需来源/处置/约束/任务/验证且无阻塞冲突。必需执行项的所有必需断言须通过，并绑定最终 planHash、snapshotHash、environmentHash、testSpecHash；旧方案通过、FAILED/INCONCLUSIVE/NOT_RUN 均不能替代。
- 改方案后重新执行受影响验证；确定性证明不受影响的结果须显式重绑定，原记录不可改写。A1 仅在约定无需执行时可用完整验证计划和 NOT_RUN 完成。

### MIG-R14 接口、事件与凭据

- 新 /api/migrations 接口提供创建、状态、任务、事件、问题/回答、取消/恢复、计划、产物、验证作业、决策及导出；旧接口保持既有契约。
- 提交与回答具有宿主幂等键；创建返回真实 run/revision；事件有序并可按游标重连，进度与终态来自 PG。
- 凭据失效或重启丢失时要求重新绑定；错误只返回稳定码及受控引用。

### MIG-R15 工作台与历史

- 工作台展示三模式、实际/声明版本、证据、调查任务、方案比较、开发工作项、验证/决策和历史差异。
- 草案、封存、未验证、候选和未知明确可见；不显示虚构百分比或把 NOT_APPLICABLE 投影当成功验证。
- 输入校验、中文错误、键盘可用性、桌面/窄屏、断线回读与 JSON/Markdown 一致性均需验收。

### MIG-R16 预算、缓存与运维

- 共享账本对调用/token/时间/并发/文件对象数/重试/验证资源预留和结算；并行任务不能超用同一预算。原采集器限制继续有效。
- 缓存绑定来源、工具、规则、目标条件和数据策略；模型产物另绑定模型及提示版本。来源/约束变化沿引用关系使受影响结果失效，历史封存不改写。
- 日志记录受控事件、哈希、耗时和错误，不记录隐藏思考。备份覆盖状态、checkpoint 和产物；垃圾回收不能删除被封存方案引用的证据。

### MIG-R17 兼容与迁移发布

- 旧 Agent v1/v2、调查报告 v1–v5、CLI、预览、哈希与旧数据库迁移校验和必须保留兼容；新增命名空间不重写历史 JSON。
- 新编排开关不让旧编排器接管新运行；关闭后仍可读新历史，未完成新运行按匹配版本恢复或显式重新运行。
- 现有候选关系不能原地升级为确定事实；Neo4j/检索索引保持可重建投影。

### MIG-R18 分阶段交付

- 按 P0 契约/恢复原型→P1 草案闭环→P2 语义/方向规则→P3 隔离验证→P4 扩展执行，每阶段有独立出口证据，见任务文档。
- 每批更新必须包含源码必要注释、契约样例、支持矩阵、失败行为和验证记录。空接口、模拟成功及只勾选任务不算交付。

### MIG-R19 质量验收

- 覆盖 MD-AC01–28，分开记录离线测试、真实模型、厂商实库、浏览器及故障恢复；缺环境记阻塞/未执行，不记通过。
- 样例覆盖三模式、正反例、证据不足和故障，记录遗漏、误报、无依据建议、人工修改量、成本及时延；不能只评价报告是否生成。

### MIG-R20 追踪与变更管理

- requirements 定义行为，design 定义契约与实现边界，tasks 定义顺序/产物，check_list 保存验收条件及后续证据。
- 当前源文档 MD-D/MD-AC 与本组 MIG 编号建立映射；旧 INV 编号和历史记录留在归档，不改写原日期或把历史测试数算作本次通过。
- 影响范围、上下文外发或执行模式的变更，需同步实现规格、工程约束、权限配置和验收项。

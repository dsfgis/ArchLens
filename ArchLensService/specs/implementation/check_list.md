## 1. 状态及证据口径

**下列 28 项新产品验收全部为待实现、未执行。** 文档重建、既有单元测试或历史模型/数据库验证不构成 LangGraph、新方案、语义绑定或隔离验证已通过。现有能力可以复用，但接入新协议与编排后必须按对应范围验收。

| 状态 | 使用条件 |
| --- | --- |
| 待实现 / 未执行 | 尚无该能力或本轮未运行；不得显示通过 |
| 已实现待验证 | 有真实实现，尚未取得规定范围的验证证据 |
| 部分通过 | 明确列出已通过子范围和剩余项；总项保持未通过 |
| 阻塞 | 缺少指定模型、厂商实例、权限、样本或业务决策；记录解除条件 |
| 失败 | 实际结果不满足断言；保留错误和反例，关联修复任务 |
| 通过 | 规定范围与必需正反例全部满足，证据可读取且哈希一致 |
| 不适用 | acceptanceScope 明确排除，记录理由与确认；不能替代必需项 |

每条通过记录至少包含：执行日期、代码 commit 与未提交补丁摘要/哈希、Schema/规则/工具/模型版本、样例与输入哈希、环境版本/兼容模式、命令或操作步骤、预期及实际断言、证据位置/哈希、失败/跳过项、评审者及适用范围。含敏感信息的原始证据在受控存储保留，仓库仅记不含秘密的引用。

离线桩、真实模型、ArchLens 自身 PG/Neo4j、各业务数据库、浏览器及故障注入分别记结果。数据库连接成功不等于结构覆盖完整；用桩完成调度不等于真实模型会正确选工具；样例行为一致不等于整项目迁移等价。

表中 R/D 对应 MIG-R/MIG-D，T 对应 MIG-T；所有 AC 使用源设计的 MD-AC 编号，不另设含义不同的同号条目。

## 6. 评测样本与质量记录

- 至少分别包含代码、数据库、联合模式；每个已发布迁移方向保留支持例、反例、歧义、缺证据、权限不足及故障样例。
- 首例至少包含一个真实不兼容特征、一个可补查缺口和一个业务不变量；固定源/目标版本及模式。
- 记录遗漏、误报、无依据建议、人工修改量、阶段耗时、模型调用/token/费用及失败原因；注明样本规模和分母，不用单一“成功率”掩盖未覆盖项。
- 模型评测保留模型配置、提示/工具版本及受控请求摘要；离线桩结果独立。不要保存隐藏思考或将其用作事实依据。
- 具体质量/性能阈值在对应任务的样本基线上确定并冻结；未测量时不填写虚构的准确率、吞吐或两个月全覆盖承诺。

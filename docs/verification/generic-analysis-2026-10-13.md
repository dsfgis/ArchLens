# 通用分析入口与模型配置验证（2026-10-13）

## 实施范围

- 首页只收自然语言目的、代码库路径、可选业务数据库连接、目标环境与通用约束；技术场景、源/目标产品和版本由后台从目标文字、本地项目声明及可选目标环境判断。文件清单可留空，由 Node 在授权根目录有界发现并在正式请求中封存。仅数据库模式可不提供代码根目录。
- Java `RepositoryInspector` 只读授权清单，识别语言候选、Maven 中 Java/Spring Boot 等直接声明、.NET 工程声明、包声明和 Go 模块；未知或条件配置保留缺口。模型只看白名单产品/版本和匿名证据摘要，不接收路径、源码、项目名和数据库凭据。
- `AgentOrchestrator` 增加检查工具与最多两个顺序执行的子调查委派，父子共享调用次数、工具次数和截止时间；子调查不能递归委派。子报告、澄清与诊断保留在封存报告中。确定性规则仍是权威兼容判断。
- 模型服务通过后端 `ARCHLENS_LLM_*` 指定 Chat Completions 端点、模型标识和密钥，支持本机无密钥模型与旧 `DEEPSEEK_*` 配置。页面的配置状态只显示标签与模型名。
